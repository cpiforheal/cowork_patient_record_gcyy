# 岗位角色与权限矩阵

## 授权原则

服务端角色目录是唯一授权来源。有效请求必须同时满足：账号启用、角色能力、活动科室授权、患者或任务范围以及当前业务状态。前端菜单和按钮仅反映服务端结果，不能替代接口鉴权。

- 普通临床岗位只访问活动科室归属、显式跨科授权或本人病例岗位范围内的数据。
- 病例岗位分配只扩展数据范围，不能赋予角色本身没有的阶段能力。
- 账号角色、科室、状态或密码变化后，全部旧会话立即失效。
- `admin` 可全局只读排障，但不能写临床事实、生成病历或完成临床阶段。
- `quality` 可全局只读并执行质控、退回和归档，不改写原始事实。
- `manager` 仅访问汇总和导出；`display` 仅访问脱敏大屏。

## 规范角色

| 角色代码 | 岗位 | 核心职责 | 数据范围 |
|---|---|---|---|
| `admin` | 系统管理员 | 账号、科室、系统配置、备份和数据维护 | 全局只读排障；无临床写权限 |
| `manager` | 院办/管理 | 运营汇总、管理看板、报表导出 | 汇总数据，不访问患者明细 |
| `quality` | 质控/病案 | 质控审核、退回、归档、套餐及周度规则 | 患者全局只读；质控动作可写 |
| `display` | 展示终端 | 检查接诊及中药房叫号展示 | 仅脱敏大屏数据 |
| `frontdesk` | 前台登记 | 建档、登记、发号、收费确认 | 活动科室及明确授权病例 |
| `reception` | 接诊 | 接诊事实、接诊队列 | 活动科室、授权或分配病例 |
| `inspection` | 检查室 | 初检、肠镜任务、检查队列 | 活动科室、授权或分配病例 |
| `tcm` | 中医 | 中医阶段、电子处方开立 | 活动科室、授权或分配病例 |
| `doctor` | 医生 | 诊断、复核、病历生成与定稿 | 活动科室、授权或分配病例 |
| `nurse` | 护理/治疗 | 手术执行事实、生命体征 | 活动科室、授权或分配病例 |
| `lab` | 化验室 | 化验辅助任务 | 活动科室、授权或分配病例 |
| `ecg` | 心电室 | 心电辅助任务 | 活动科室、授权或分配病例 |
| `ultrasound` | B超/放射 | 影像辅助任务 | 活动科室、授权或分配病例 |
| `warehouse` | 仓库 | 入库、审批、发放、调拨、盘点、报损和库存异常 | 中央仓、在途库及授权库位 |
| `tcm_pharmacy` | 中药房综合岗 | 审方、调剂、代煎、叫号和领取 | 中药房业务数据 |

历史角色只在迁移时接受：`nursing` 归并为 `nurse`；`tcmPharmacyOperator`、`pharmacist`、`pharmacy`、`decoction` 归并为 `tcm_pharmacy`。历史代码不能再分配给新账号。

## 进销存职责

- 临床岗位：本科室库存查看、申领、签收、科室盘点。
- `warehouse`：物资档案、入库、申领审批、发放、调拨、中央仓盘点、报损和库存异常重试。
- `quality`：患者耗材套餐、每患者标准、周度快照确认、追溯和导出。
- `manager`：管理汇总和导出，不执行库存操作。

## 审查清单

新增接口或按钮时必须同时补充服务端 capability、角色目录说明、正向测试和至少一个无权角色的 403 测试。不得通过前端角色判断、客户端提交的操作者角色或病例岗位分配绕过服务端策略。
