# 进销存模块 PRD、统计口径与岗位 SOP

> 文档版本：3.0
> 适用范围：中央仓库、科室库存、患者阶段耗用、周度对账、审计导出

## 1. 产品目标与边界

本模块把“建档与入库、申领与签收、病历阶段自动耗用、周度预估与实际对账”统一到可查询、可导出、可审核的服务端账本中。

本版本覆盖物资档案、批次入库、科室期初、申领审批、发放签收、科室套餐、关键阶段自动耗用、异常重试、冲销补扣、周度标准、快照确认、XLSX/PDF/DOCX 导出和线下签字。

本版本不覆盖采购订单、供应商、付款、发票、财务凭证、电子签名、签字图片或多人电子签署流。

## 2. 信息架构与兼容

左侧只显示四个一级入口，相近能力放入入口内页签：

| 一级入口 | 默认路由 | 内部页签与原路由 |
| --- | --- | --- |
| 工作台 | `/inventory/overview` | 运营总览 `/inventory/overview`、领导视图 `/inventory/executive` |
| 库存作业 | `/inventory/requests` | 申领审批签收 `/inventory/requests`、库存批次 `/inventory/stock`、盘点控制 `/inventory/controls` |
| 耗材规则 | `/inventory/packages` | 物资档案 `/inventory/items`、门诊/住院套餐与扣减异常 `/inventory/packages` |
| 周度对账 | `/inventory/weekly` | 每患者标准量与周度快照 `/inventory/weekly`、追溯流水 `/inventory/trace` |

旧路由继续注册为隐藏菜单，并通过 `meta.activeMenu` 高亮所属新入口。`/inventory/manage` 显式重定向到 `/inventory/overview`。刷新、收藏和分享旧深链接后仍定位到对应业务页签。

## 3. 权限与数据边界

- 一级入口：用户拥有任一内部页签查看权限即显示。
- 内部页签：沿用原菜单权限和按钮能力，不重命名权限编码。
- 操作按钮：继续使用审批、发放、维护、确认、导出和重试等细粒度权限。
- 无权页签：跳到同一入口第一个有权页签；整个入口无权时返回 403。
- 服务端接口继续执行写权限和科室数据范围校验，前端隐藏按钮不能替代后端鉴权。

病历创建后锁定归属科室。耗用、冲销和报表均按病历归属科室统计，不跟随操作者当前活动科室变化。

## 4. 库存账本

### 4.1 三类库位

- 中央仓库：入库、审批锁定、发放出库和退库接收。
- 在途库位：中央仓库已发放、科室尚未签收。
- 科室库存：签收后可被患者关键阶段实际耗用。

### 4.2 流转规则

1. 入库增加中央仓库库存。
2. 审批只锁定中央仓库可用量，不改变账面数量。
3. 发放使中央仓库减少、在途增加，不计入患者耗用。
4. 签收使在途减少、科室库存增加，不计入患者耗用。
5. 关键阶段耗用从病历归属科室库存扣减，计入实际量。
6. 退库、报损和盘点作用于明确库位并单独列示。
7. 阶段退回和纠错通过冲销/补扣修正，不删除原流水。

申领作废只改变申领/调拨流程，不等于患者耗用冲销。

## 5. 患者自动扣减

### 5.1 登记边界

患者登记只计入科室本周患者量和预估量，不立即减少库存。这样可避免“已登记但未完成治疗”提前扣库。

### 5.2 触发阶段

阶段完成后投递异步耗用命令：

- `INSPECTION`：检查。
- `TCM`：中医。
- `DOCTOR`：医生。
- `SURGERY`：手术。

### 5.3 套餐匹配

匹配维度为病历归属科室、门诊/住院、阶段、生效日期和最新启用版本。就诊类型仅 `inpatient` 归住院，其他值或空值按当前实现归门诊。

套餐每行数量表示“每患者在该阶段的标准数量”。实际执行用量与套餐不同时，按现有差异机制形成最终耗用清单。

### 5.4 幂等、一致性和 FEFO

每个“病历 + 阶段 + 完成版本 + 命令类型”只允许一条有效任务。重复完成、网络重试和服务重启不会重复扣减。

科室库存按现有 FEFO 查询顺序分配：有有效期的批次按日期靠前优先，无有效期批次排在最后。成功耗用、批次明细和库存流水在同一事务中完成。

当前查询没有单独排除已过期批次。本版本如实保留该算法边界，不擅自改变库存规则；是否强制排除过期批次列入后续业务确认。

### 5.5 整套失败和医疗解耦

期初未确认、套餐缺失、套餐为空或库存不足时，整套失败且不进行部分扣减。失败不会阻断医疗阶段完成，而是进入扣减异常中心。修复期初、套餐或库存根因后重试原幂等任务。

### 5.6 退回和纠错

- 阶段退回：未执行任务取消；已执行任务按原批次冲销并恢复库存。
- 阶段纠错重做：先冲销旧完成版本，再按新完成版本补扣。
- 原耗用和冲销流水均保留操作者、原因、时间、批次和关联命令。

## 6. 周度标准与快照

### 6.1 标准清单

标准按科室、门诊/住院和物资维护：

- 每患者标准耗材量。
- 计划患者量。
- 标准单位和库存基础单位。
- 换算系数。
- 安全库存。

草稿可编辑，发布后按版本和生效周参与快照生成。

### 6.2 计算口径

```text
患者量 = 科室本周实际登记的门诊或住院患者数
计算患者量 = 实际患者量 > 0 ? 实际患者量 : 计划患者量
预估量 = 每患者标准量 x 计算患者量 x 换算系数
实际量 = 成功耗用流水 - 冲销流水
差异 = 预估量 - 实际量
```

差异为负表示实际耗用高于预估。`sourceSummary` 保存患者来源、实际/计划患者数、每患者标准量、换算系数和扣减流水数量，保证页面与导出可追溯。

### 6.3 确认、更正与导出

- 新快照为草稿；确认后作为正式对账版本。
- 更正创建修订版并保留原版本，不覆盖历史。
- XLSX、PDF、DOCX 使用同一快照数据。
- 未确认快照标记“草稿/待确认”，已确认快照标记“正式版/已确认”。
- 导出包含制表、科室负责人、复核和日期签字栏，并记录导出人、时间和审计事件。

## 7. 岗位 SOP

### 7.1 管理员/质控初始化

1. 核对物资、单位、批次和效期。
2. 核对账号科室关系与病历归属科室。
3. 盘点并确认中央仓库及科室期初。
4. 配置并启用四个关键阶段的门诊/住院套餐。
5. 发布每患者周度标准。
6. 用测试病历验证登记、完成、重复完成、退回、纠错和异常重试。

### 7.2 中央仓库

1. 处理入库并核对批次、效期和位置。
2. 审核申领并检查可用量。
3. 发放后关注逾期未签收和低库存/临期事项。
4. 退库、报损和盘点必须选择明确库位并记录原因。

### 7.3 科室岗位

1. 提交申领并由负责人审核。
2. 收货时核对物资、批次、数量和效期后签收。
3. 临床岗位正常完成业务阶段，不重复录入套餐耗材。
4. 需要退回或纠错时走原医疗流程，不直接改库存流水。

### 7.4 异常处理

1. 查看病历、归属科室、阶段、完成版本和失败原因。
2. 修复期初、套餐或科室库存问题。
3. 重试原任务，禁止另建人工耗用绕过失败。
4. 对退回/纠错检查冲销和补扣状态。

### 7.5 周末对账和签字

1. 选择周次和科室生成快照。
2. 核对患者来源、标准量、预估、实际和差异。
3. 填写人工调整和原因，需要时创建更正版本。
4. 负责人确认快照。
5. 导出 XLSX、PDF 或 DOCX，完成线下签字和归档。

## 8. 验收矩阵

- 四个一级入口按角色正确显示，旧九路由和 `/inventory/manage` 可解析并正确高亮。
- 无权页签回退到组内首个有权页签，整组无权返回 403；按钮继续按细粒度权限控制。
- 登记患者不扣库存，检查/中医/医生/手术完成后扣减。
- 重复完成幂等；套餐缺失、套餐为空、库存不足、期初未确认整套失败。
- 阶段退回按原批次冲销，纠错先冲销旧版本再补扣新版本。
- 实际患者量优先、计划患者量回退，预估公式和差异符号正确。
- 草稿/正式导出状态、三种格式、签字栏及审计记录正确。
- 1366x768、1440x900 和较窄桌面下无重叠、截断或重复导航。

## 9. 发布与回滚

发布前运行后端测试、前端校验和生产构建。便携包先生成到独立暂存目录，不能直接覆盖运行中的 `release\clinic-portable`。

更新 8848 时必须保留原数据库、附件、配置和本机密钥。先停止当前服务，备份并更新应用运行文件，恢复原数据配置后重新启动；验证健康、登录、四入口菜单和关键业务闭环。

如启动或验证失败，恢复匹配版本的应用包和数据配置，不得只回滚程序并保留不兼容数据，也不得另开端口规避失败。
