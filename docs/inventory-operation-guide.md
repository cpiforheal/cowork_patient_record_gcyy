# 进销存模块操作指南

> 适用对象：管理员、质控、仓库人员、科室负责人、临床及辅助岗位、管理者
> 核心原则：患者登记形成患者量和预估量，关键阶段完成才形成实际库存扣减。
>
> 开发说明：前端 `src/assets/json/authMenuList.json` 仅用于本地开发和界面联调的菜单样例，不参与生产运行。生产环境的菜单、可见范围和按钮能力统一以服务端 `GET /auth/navigation` 返回结果为准。

## 一、闭环总览

系统按实际任务提供九个入口：

| 顺序 | 任务入口     | 用途                                    |
| ---- | ------------ | --------------------------------------- |
| 1    | 今日待办     | 查看当前指标、待办和库存风险            |
| 2    | 管理看板     | 查看管理指标、科室消耗和风险汇总        |
| 3    | 申领与签收   | 完成申领、审批、发放、签收和撤销        |
| 4    | 入库与库存   | 完成入库并查看中央、在途和科室库存批次  |
| 5    | 盘点与报损   | 处理盘点、科室退库、报损和差异说明      |
| 6    | 患者耗材套餐 | 维护门诊/住院阶段套餐并处理扣减失败任务 |
| 7    | 周用量核对   | 维护周度标准、生成快照、核对差异并确认  |
| 8    | 出入库记录   | 查询和导出库存流转、耗用及冲销记录      |
| 9    | 物资设置     | 维护物资名称、规格、单位、效期和预警线  |

### 1.1 角色可见性

菜单可见性由服务端能力集决定，不由前端样例或角色名称自行推断。当前授权基线如下：

| 岗位         | 可见入口                                                                       |
| ------------ | ------------------------------------------------------------------------------ |
| 管理员、质控 | 九个入口全部可见；具体写操作仍由按钮能力控制                                   |
| 管理者       | 今日待办、管理看板、患者耗材套餐、物资设置；默认只读，导出能力以服务端授权为准 |
| 科室业务岗位 | 今日待办、申领与签收、患者耗材套餐、周用量核对；仅可处理授权科室和本岗位动作   |

仓库人员、科室负责人、临床及辅助岗位若使用定制账号，实际入口和按钮以服务端为该账号下发的能力集为准。

标准业务顺序：

1. 建立物资档案、单位换算和科室期初库存。
2. 按科室、门诊/住院和关键阶段配置启用套餐。
3. 设置每患者标准耗材量、计划患者数、换算系数和安全库存。
4. 仓库入库，科室申领，依次完成审批、发放和签收。
5. 患者登记计入本周患者量和预估量，但不直接扣减库存。
6. 检查、中医、医生或手术阶段完成后，系统异步执行套餐耗用。
7. 周末生成快照，比较预估量、实际量和差异。
8. 负责人确认快照，导出正式文件，完成线下签字和归档。

## 二、管理员初始化

### 2.1 物资与库存

1. 在“物资设置”维护名称、规格、基础单位、批号/效期要求和预警线。
2. 核对中央仓库批次、数量、效期和位置。
3. 按实物盘点确认各科室期初库存。期初未确认的科室不会自动扣减，只会产生异常任务。
4. 单位存在换算时，确认套餐标准单位、库存基础单位和换算系数一致。

### 2.2 套餐

1. 在“患者耗材套餐”选择病历归属科室。
2. 区分门诊和住院，并选择关键阶段：检查、中医、医生或手术。
3. 维护每种物资的每患者/阶段数量、生效日期和版本。
4. 检查清单不为空后启用。系统只匹配生效日期内最新的启用版本。
5. 套餐变更应创建新版本，历史耗用继续保留原套餐版本。

### 2.3 周度标准

在“周用量核对”按科室和门诊/住院维护每患者标准量：

- 每患者标准耗材量。
- 计划患者数，用于本周没有实际登记患者时的回退计算。
- 换算系数，用于将标准单位换算为库存基础单位。
- 安全库存，用于形成建议补领量。

标准发布后再生成周度快照，避免使用未审核草稿。

## 三、仓库与科室日常操作

### 3.1 仓库入库

1. 在“入库与库存”选择物资。
2. 输入数量、批号、有效期、位置和来源。
3. 对要求批号或效期的物资完整填写对应字段后保存。

### 3.2 科室申领到签收

1. 科室人员在“申领与签收”新建申领。
2. 负责人审核。审核只锁定中央仓库可用量，不形成患者实际耗用。
3. 仓库按批次发放，中央仓库减少、在途库存增加。
4. 科室核对实物、数量、批号和效期后签收，在途减少、科室库存增加。
5. 申领作废只处理该申领/调拨单，不等于患者耗用冲销。患者耗用必须通过阶段退回或纠错形成冲销任务。

### 3.3 日常检查

- 仓库每天处理待审核、待发放、待签收和低库存/临期事项。
- 科室每天完成签收并核对科室库存。
- 盘点差异、退库和报损必须选择明确库位并填写原因，不能直接改库存余额。

## 四、患者自动扣减

### 4.1 登记与扣减边界

患者登记只完成两件事：计入科室本周门诊/住院患者量，并参与预估量计算。登记完成不会减少库存，避免患者登记后未实际治疗就提前扣库。

实际扣减由以下关键阶段完成触发：

- `INSPECTION`：检查阶段。
- `TCM`：中医阶段。
- `DOCTOR`：医生阶段。
- `SURGERY`：手术阶段。

### 4.2 匹配和幂等

套餐按“病历归属科室 + 门诊/住院 + 阶段 + 生效日期 + 最新启用版本”匹配。当前就诊类型为 `inpatient` 时归住院，其他值或空值归门诊。

每个“病历 + 阶段 + 完成版本 + 命令类型”只能生成一条有效耗用任务。重复点击完成、网络重试或服务重启不会重复扣减。

### 4.3 扣减执行

系统按现有 FEFO 顺序选择科室库存：有有效期的批次按日期靠前优先，无有效期批次排在最后。成功后写入耗用事件、批次分配和库存流水。

以下情况整套失败，不进行部分扣减：

- 科室期初未确认。
- 没有匹配到套餐。
- 套餐明细为空。
- 任一物资库存不足。

库存异常不会阻断医疗阶段完成。任务进入“患者耗材套餐”的扣减失败任务列表，修复根因后对原任务重试。

### 4.4 退回和纠错

- 阶段退回时，未执行任务取消；已执行任务按原批次冲销并恢复库存。
- 阶段纠错重做时，先冲销旧完成版本，再按新完成版本补扣。
- 冲销保留原耗用、批次、操作者、原因和时间，不删除历史流水。

## 五、异常处理

| 异常           | 处理动作                                               |
| -------------- | ------------------------------------------------------ |
| 期初未确认     | 先按实物盘点并确认科室期初，再重试原任务               |
| 套餐缺失       | 按科室、门诊/住院和阶段新增并启用套餐，再重试          |
| 套餐为空       | 补齐套餐物资明细并启用新版本，再重试                   |
| 库存不足       | 入库或完成申领、发放、签收，使科室库存充足后重试       |
| 疑似重复扣减   | 按病历、阶段、完成版本核对任务和流水，禁止直接改数据库 |
| 退回未恢复库存 | 核对冲销任务状态；修复失败原因后重试冲销任务           |

异常处理遵循“修根因、重试原幂等任务”的原则，不另建人工耗用绕过失败记录。

## 六、周用量核对与签字

### 6.1 统一口径

```text
患者量 = 科室本周实际登记的门诊或住院患者数
计算患者量 = 实际患者量 > 0 ? 实际患者量 : 计划患者量
预估量 = 每患者标准量 x 计算患者量 x 换算系数
实际量 = 执行成功的耗用流水 - 冲销流水
差异 = 预估量 - 实际量
```

差异为负表示实际耗用高于预估。页面和导出同时展示实际/计划患者数、标准量、换算系数、预估量、实际量、差异、建议补领、人工调整和审计来源。

### 6.2 周末操作

1. 在“周用量核对”选择周次和科室并生成周度快照。
2. 展开明细，核对患者来源、扣减流水数量和差异。
3. 对异常差异填写调整原因；需要更正时生成新修订版，不覆盖旧版本。
4. 负责人确认后，快照状态变为已确认。
5. 导出 XLSX、PDF 或 DOCX。未确认快照标记“草稿/待确认”，已确认快照标记“正式版/已确认”。
6. 导出文件填写制表、科室负责人、复核和日期签字栏，完成线下签字和归档。系统同时记录导出人、导出时间及审计事件。

## 七、当前边界

- 系统确认、审计日志和导出文件线下签字构成本轮签字边界，不包含电子签名、签字图片或多人电子签署流。
- 当前 FEFO 查询按有效期排序，但没有单独实现“自动排除已过期批次”。仓库必须先隔离和处理过期批次；是否由系统强制排除需后续业务确认。
- 周度快照用于耗材管理和补领建议，不直接创建采购订单、付款或财务凭证。
