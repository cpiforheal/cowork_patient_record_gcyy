# 受控业务数据清理与恢复

## 清理边界

该功能用于试运行数据归零。执行后仅保留 `admin`、规范角色目录、科室、字典、字段规则、AI 配置、队列房间和打印配置、备份配置、Flyway 历史，以及中央仓、配送在途和有效科室库位。

患者、就诊、前置病历、旧病历、附件引用、生成文书、队列业务、打印任务、中药房业务、AI 助手日志、数据库快照、库存物资及全部业务流水均会清空。普通账号和旧会话也会删除。

## 执行流程

1. 使用 `admin` 打开“系统管理 -> 数据维护”，先执行预检。
2. 核对各业务域计数、受管文件数量、保留项和数据库修订号。
3. 输入当前管理员密码和页面显示的确认文本。
4. 系统进入维护锁，拒绝其他业务写入。
5. 系统在 `data/manual-clean-backups/purge-<timestamp>` 创建保护备份，并校验数据库 dump、文件清单和 SHA-256。
6. 系统按外键和业务引用顺序在单个数据库事务中删除数据，不使用 `TRUNCATE`，不关闭外键。
7. 数据库提交后，将活动受管目录移动到 quarantine 并创建空目录。
8. 页面展示清理运行编号、保护备份位置、清理前后计数和文件隔离状态。

受管目录包括 `attachments`、`generated-pre-ai`、`generated-medical-records`、`medical-record-workflow` 和 `generated-ai-documents`。目录不存在时跳过，但会在清单中记录。

## 成功条件

- 患者、病历、队列、中药房、AI 日志、数据库快照及库存业务表均为 0。
- `clinic_accounts` 仅保留 `admin`，角色目录为 15 个规范角色，旧会话为 0。
- 库位只有中央仓、配送在途和每个有效科室各一条；科室期初状态为未确认。
- 活动受管目录为空，保护备份和 quarantine 均存在且哈希可复核。
- 科室、字典、AI、队列房间、打印和备份配置仍可读取。

## 失败与恢复

- 保护备份失败时不允许开始删除。
- 数据库事务失败时自动回滚，活动文件保持不变。
- 数据库已提交但文件隔离失败时，运行记录标记为部分完成；重新执行文件隔离，不再次删除数据库。
- 需要整体回退时，先停止 8848，使用保护备份目录内的恢复脚本恢复数据库和受管目录，再启动服务并核对健康接口和表计数。
- quarantine 和保护备份不会自动删除。确认新系统数据已正常运行后，才可另行批准永久删除。
